# AI-ассистент руководителя — ООО «Фотопринт»

AI-ассистент берёт на себя рутину руководителя: готовит встречи, превращает
разговоры и переписку в поручения, следит за сроками и проверяет, сработали ли
принятые решения. **Ассистент только предлагает — любое действие выполняется
после подтверждения человеком.** Все данные в репозитории синтетические.

Прототип подготовлен для хакатона «Фабрика идей» (трек 3).

## Что получает руководитель

| Возможность | Что происходит |
|---|---|
| **«Мой день»** | Показатели (брак, заказы в срок, SLA, просрочки), всё, что требует решения, просроченные поручения, кому делегировать задачи без владельца — с основанием |
| **Решения «до/после»** | Отклонение показателя → разбор по разрезам → гипотеза причины с источниками → решение с ответственным и сроком → после срока система сама пересчитывает показатель и показывает, сработало ли решение |
| **Встречи** | Повестка из документов, переписки и незакрытых поручений → свободное время участников → приглашение с файлом календаря → протокол из расшифровки → поручения → рассылка итогов |
| **Поручения голосом** | Руководитель диктует «Дима, проведи испытания до пятницы» — ассистент определяет исполнителя, срок и результат и готовит карточку |
| **Вопросы ассистенту** | Ответ только с цитатой первоисточника. Если данных нет — «недостаточно данных» и подсказка, кто может знать |
| **Источники и граф компании** | Документы, почта, Telegram-группы и рабочие чаты связаны в граф людей, поставщиков, партий и поручений; у каждой связи — первоисточник |
| **Сторож договорённостей** | Находит обещания в переписке («пришлю до пятницы») и расхождения с реестром поручений |
| **Обратная связь** | 👍/👎 у ответа и протокола с комментарием «что не так»; в протоколе можно добавить пропущенный пункт к любой реплике, поменять вид и статус пункта, поправить краткое содержание |

## Почему этому можно доверять

- **Ничего не происходит без человека.** Каждое действие — письмо, встреча,
  поручение, решение — оформляется карточкой с предпросмотром; выполняется
  только подтверждённая версия. Журнал аудита хранит, кто что спросил, какие
  источники нашёл поиск и на какие сослался ответ; телефоны, счета, паспорта и
  ключи маскируются.
- **Права проверяются до поиска.** Ассистент видит только то, что доступно
  пользователю. Переписку видят лишь её участники — даже директор не читает
  чужие чаты. Оклады и персональные данные в ИИ не передаются никогда.
- **Ассистент не выдумывает.** Каждое утверждение опирается на цитату, которую
  сервер сверяет с источником — и по тексту, и по смыслу: обещание «направим
  до 13.11» не может стать фактом «сертификат поступил», а предложение — решением.
  Числа, даты, сроки и показатели считает код, а не модель.
- **Текст документов — данные, а не команды.** Попытки «приказать» ИИ через
  документ или сообщение распознаются и не выполняются.
- **Видно, где работает модель:** в контуре компании или во внешнем API.
  Скрытого переключения во внешний сервис нет.

## Где работает модель

| Вариант | Для чего |
|---|---|
| **Модель в контуре компании** (`LLM_PROVIDER=local`) | Основной путь для внедрения: любой OpenAI-совместимый сервер, например vLLM на GPU-серверах заказчика (2×H200). Документы и переписка не покидают контур. Меняется только адрес модели — код тот же. Подробно — [docs/deployment.md](docs/deployment.md) |
| **Gemini, GPT или Claude по API** (`LLM_PROVIDER=gemini` / `openai` / `anthropic`) | Демонстрация без собственного GPU-сервера; провайдер выбирается одной строкой в `.env` |
| **Ollama на рабочей станции** (`LLM_PROVIDER=ollama`) | Проверка на ноутбуке с NVIDIA GPU. На RTX 4060 (8 ГБ) модель Qwen3 4B помещается, но её качества для протоколов недостаточно — нужна модель крупнее, которая работает на серверах заказчика |

## Запуск

**Нужно:** Git и запущенный Docker Desktop (Windows, WSL 2) или Docker Engine
с Compose (Linux), доступ в интернет для загрузки образов. Для внешней модели —
ключ API (Gemini, OpenAI или Anthropic); для модели в контуре — адрес её сервера.
Что модель доступна ключу, показывает http://localhost:8000/health.

1. Скопировать настройки:

   ```bash
   cp .env.example .env
   ```

   В PowerShell: `Copy-Item .env.example .env`.

2. В `.env` выбрать модель (один вариант) и задать время демо-сценария:

   ```dotenv
   # Gemini
   LLM_PROVIDER=gemini
   GEMINI_API_KEY=<ключ>
   GEMINI_MODEL=<модель Gemini, доступная вашему ключу>

   # или GPT
   # LLM_PROVIDER=openai
   # OPENAI_API_KEY=<ключ>
   # OPENAI_MODEL=<модель, доступная ключу>

   # или Claude
   # LLM_PROVIDER=anthropic
   # ANTHROPIC_API_KEY=<ключ>
   # ANTHROPIC_MODEL=<модель, доступная ключу>

   # или модель в контуре компании
   # LLM_PROVIDER=local
   # LOCAL_BASE_URL=http://<gpu-сервер>:8001/v1
   # LOCAL_MODEL=<имя модели из /v1/models>

   SCENARIO_NOW=2026-11-11T12:00:00+03:00
   JWT_SECRET=<любая длинная случайная строка>
   ```

   `SCENARIO_NOW` фиксирует «сегодня» демо-набора, чтобы сроки и показатели
   совпадали со сценарием. Файл `.env` в репозиторий не попадает.

3. Запустить и загрузить демо-данные:

   ```bash
   docker compose up -d --build
   docker compose exec api python -m app.cli reset
   ```

   Для Ollama на ноутбуке с GPU: `LLM_PROVIDER=ollama`, `LLM_MODEL=qwen3:4b`
   в `.env` и `docker compose --profile gpu up -d --build` — модели скачаются сами.

4. Открыть http://localhost:8080 и войти:

   | Логин | Роль | Что видит |
   |---|---|---|
   | `director` | Директор | Всю компанию; чужая переписка недоступна |
   | `morozov` | Руководитель производства | Своё подразделение и переписку со своим участием |

   Пароль — `DEMO_PASSWORD` из `.env` (по умолчанию `fokus-demo`). На странице
   входа есть кнопки быстрого входа под этими ролями.

| Адрес | Что там |
|---|---|
| http://localhost:8080 | Интерфейс |
| http://localhost:8025 | Почтовый ящик стенда: приглашения, итоги встреч, напоминания |
| http://localhost:8000/health | Состояние: база, модель, почта |
| http://localhost:8000/docs | Описание API |

Если порт занят — поменяйте `WEB_PORT`, `API_PORT`, `DB_PORT` или
`MAILPIT_UI_PORT` в `.env`. После правки `.env`:
`docker compose up -d --force-recreate api`.

## Пять минут на знакомство

1. **«Мой день»** под `morozov`: брак фотокниг выше плана → «Разобрать
   отклонение» → главный вклад, гипотеза причины с источниками → «Оформить
   решение» → подтвердить карточку.
2. **«Решения»**: у решения по входному контролю наступил срок → «Проверить
   результат» — брак снизился с 4,1% до 2%.
3. **«Встречи»**: тема и участники → «Собрать повестку» → «Найти свободное
   время» → приглашение уходит в почтовый ящик стенда. Во второй вкладке —
   протокол из расшифровки, публикация, рассылка итогов.
4. **«Раздать голосом»** в «Моём дне»: продиктовать или напечатать поручение.
5. **«Ассистент»**: «Какая доля брака фотокниг была в октябре?» — ответ с
   цитатой; вопрос про оклады — отказ; вопрос, которого нет в данных, —
   «недостаточно данных» и кто может знать.

## Что проверено и что впереди

**Проверено:** 118 автоматических тестов сервера (права доступа, карточки
действий, протоколы, решения, источники, голосовые поручения, проверка смысла
цитат, аудит, подключение GPT и Claude на имитации их API); сборка
интерфейса; полный сценарий в браузере на двух ролях. На RTX 4060 с локальной
моделью Qwen3 4B — работоспособность, но не достаточное качество.

**Перед пилотом:**

- проверить живые вызовы GPT и Claude с ключами заказчика;
- подтвердить качество на выбранной модели в контуре заказчика по набору
  вопросов и эталонным протоколам из [eval/](eval/README.md);
- измерить экономию времени руководителя на реальных встречах — до измерения
  мы её не заявляем;
- подключить живые источники вместо импорта файлов: корпоративная почта
  (IMAP/Exchange), Telegram-бот, Битрикс24;
- корпоративный вход (SSO), резервное копирование, TLS;
- распознавание речи внутри контура: в прототипе речь распознаёт браузер
  (в Chrome это облачный сервис Google).

## Устройство

Интерфейс (React) → сервер (Python, FastAPI) → PostgreSQL. Сервер ищет
только по доступным пользователю данным, передаёт модели фрагменты, требует от
неё ответ по строгой схеме, проверяет цитаты и только после этого предлагает
карточку действия.

| Папка | Содержимое |
|---|---|
| `backend/` | Сервер: права, карточки действий, протоколы, решения, источники, граф |
| `frontend/` | Интерфейс руководителя |
| `data/` | Синтетический демо-набор: документы, переписка, встречи, показатели. Допущения — [data/ASSUMPTIONS.md](data/ASSUMPTIONS.md) |
| `eval/` | Проверка качества модели: вопросы и эталонные протоколы |
| `docs/` | [Развёртывание в контуре заказчика](docs/deployment.md), [источники и граф](docs/sources-graph.md) |

Автотесты: `docker compose run --rm -e LLM_PROVIDER=fake api pytest`
(`fake` — режим разработки без модели, только для тестов).
Лицензии компонентов — [LICENSES.md](LICENSES.md).
